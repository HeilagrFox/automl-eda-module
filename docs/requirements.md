# Требования

## Пользовательские сценарии

Действующее лицо во всех сценариях — аналитик.

| № | Сценарий | Цель | Основной поток |
|---|---|---|---|
| **ПС-1** | Загрузка и предпросмотр данных | Загрузить набор и убедиться в корректном считывании | Загрузка CSV/XLSX → определение разделителя и кодировки → предпросмотр первых строк, числа строк/столбцов, типов → подтверждение или ручное переопределение типа |
| **ПС-2** | Профилирование и описательные статистики | Получить обзор структуры и качества данных | Система считает профиль набора и столбцов (min, max, среднее, медиана, std, квартили; уникальные значения и частоты), долю пропусков, признаки выбросов → сводная таблица → детализация по столбцу |
| **ПС-3** | Анализ распределений | Исследовать отдельные признаки | Выбор столбца → гистограмма/плотность или диаграмма частот, диаграмма размаха, асимметрия, эксцесс, проверка нормальности → настройка числа интервалов и масштаба |
| **ПС-4** | Анализ корреляций | Выявить связи между признаками и с целью | Корреляционная матрица (тепловая карта) → выбор пары для точечной диаграммы → при заданной цели: распределение признака в её разрезе и значимость признаков → гипотезы о предикторах |
| **ПС-5** | Обработка пропусков | Обработать пропуски адаптивно | Карта пропусков и оценка механизма (MCAR/MAR/MNAR) → выбор стратегии → предпросмотр «до/после» → подтверждение или другой метод |
| **ПС-6** | Обработка выбросов | Выявить и обработать аномалии | Метод по профилю (IQR/z-оценка или DBSCAN) → пометка на визуализации → выбор действия (удаление, ограничение, замена, сохранение с пометкой) → подтверждение |
| **ПС-7** | Сравнение до и после | Осознанно оценить эффект преобразования | Для любого преобразования (импутация, выбросы, масштабирование, кодирование) наложенные распределения и изменение статистик → принять или отменить |
| **ПС-8** | Разделение на train/test | Подготовить корректное разбиение | Доля тестовой выборки и стратификация по цели → разбиение → размеры и баланс выборок |

## Системные сценарии

| № | Сценарий | Описание |
|---|---|---|
| **СС-1** | Автоматическое профилирование при загрузке | Определение типов, статистик, доли и характера пропусков, признаков выбросов, корреляций; сохранение профиля |
| **СС-2** | Классификация механизма пропусков | Оценка вероятного типа пропусков (MCAR/MAR/MNAR) для столбцов с пропусками |
| **СС-3** | Предпросмотр трансформации | Расчёт результата стратегии без необратимого изменения данных; подготовка данных для сравнения «до/после» |

## Нефункциональные требования

### Производительность и масштабируемость

- Загрузка и предпросмотр набора до 100 МБ (сотни тысяч строк) выполняются за время, приемлемое для интерактивной работы; для предпросмотра используется частичное считывание.
- Профилирование идёт в фоне, без блокировки интерфейса, с индикатором прогресса.
- Графики остаются отзывчивыми за счёт агрегации и сэмплирования.
- Архитектура разделена на клиент и сервер, тяжёлые операции выполняются на сервере и допускают вынесение в асинхронные задачи.

### Удобство использования

- Принцип low-code/no-code: основные операции доступны без кода.
- Рекомендации сопровождаются пояснениями, преобразования визуальной обратной связью «до/после».
- Единообразные UI-компоненты (таблицы, графики распределений, корреляционные матрицы) на основе Ant Design и Ant Design Charts.

### Взаимодействие системы

- REST-API, обмен в формате JSON; входные форматы CSV, XLSX.
- Для больших наборов используются загрузка файлов и ссылки на серверные артефакты.
- Базовая версия хранит состояние (профиль, текущие данные) в памяти серверного процесса для одного активного набора.

### Логирование

- Операции анализа и предобработки фиксируются в структурированном журнале: тип операции, параметры, затронутые столбцы, время.
- Системные события (ошибки чтения, превышение лимитов, сбои) логируются с уровнем серьёзности.
- В логах только метаданные и параметры, без самих значений данных.

### Отказоустойчивость

- Корректная обработка «грязных» данных (неверная кодировка, смешанные типы, аномальные значения) без аварийного завершения; понятные сообщения об ошибках.
- Промежуточные состояния хранятся в памяти, шаг можно отменить без перезагрузки набора.
