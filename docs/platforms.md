# Сравнение платформ

Анализ охватывает четыре платформы: **H2O Driverless AI**, **DataRobot**, **Azure ML** и **Polymatica ML**. Для сопоставления добавлены академические подходы **Auto-Prep** и **Preptimize**.

## Сводная таблица

| Платформа | Автоматизация предобработки | Интерактивность | Интеграция в ML-конструктор | Ограничение |
|---|---|---|---|---|
| **H2O Driverless AI** | Высокая: авто-определение сложных типов (координаты, URL, текстовые идентификаторы); генетическая эволюция признаков (feature evolution) | Богатые дашборды: распределения, важность признаков, исключение переменных, перезапуск без кода | Полная: каждая операция логируется, визуализируется, может быть отменена | Пользователь видит результат после того, как система выполнила шаги; стратегии жёстко заданы |
| **DataRobot** | Высокая: авто-определение типов, адаптивная очистка, кодирование, масштабирование | Аналогично H2O: дашборды без написания кода | Полная, единый прозрачный процесс | Нет структурированного прохождения всех этапов EDA, особенно в разрезе целевой переменной |
| **Azure ML** | Низкая: требуется явная схема данных; стандартные преобразования (one-hot, нормализация) | Ограничена: визуальный конструктор, минимальная обратная связь | Слабая: предобработка и обучение — отдельные блоки pipeline | Преобразования не адаптируются к данным; накладные расходы замедляют итерации (Bezzateev et al., 2025) |
| **Polymatica ML** | Средняя: готовые блоки (агрегация, скользящие окна, фильтрация, пропуски); упор на ручную сборку признаков | Динамические дашборды, интеграция с BI; нет сравнения распределений до/после | Семантическая: на уровне бизнес-логики, а не алгоритмов ML | Ориентирована на бизнес-аналитику, ограничены возможности глубокого EDA |

## Академические подходы

| Подход | Что реализует | Чего не хватает коммерческим системам |
|---|---|---|
| **Auto-Prep** (Bilal et al., 2022) | Визуализация проблем данных (heatmap пропусков), несколько вариантов решения, оценка каждого шага по прокси-моделям | Замкнутый цикл «предобработка → качество модели», пользователь в центре процесса |
| **Preptimize** (Usmani et al., 2024) | Профилирование как центр процесса (тип пропусков, стационарность по ADF, тренд, сезонность); генетическая оптимизация «предобработка + модель + гиперпараметры» по RMSE | Специализированная очистка временных рядов, связка очистки с прогнозной метрикой |

## Выводы по сравнению

- **Уровень интерактивности определяется аудиторией.** H2O и DataRobot ориентированы на гибкость исследования, Azure ML на технический контроль, Polymatica ML на бизнес-интерпретируемость.
- **Жёсткие стратегии есть везде.** Даже у лидеров по умолчанию применяется импутация средним, удаление выбросов по IQR и one-hot-кодирование независимо от структуры данных.
- **Адаптивная, профилируемая и обратно связанная с моделью предобработка не реализована ни в одной платформе**, хотя описана в академических работах (Fan et al., 2021; Bilal et al., 2022).
- **Временные ряды** поддерживаются на уровне лагов и скользящих окон, без учёта нестационарности, сезонности и концепт-дрейфа.

## Типичные задачи предобработки

Предобработка включает пять взаимосвязанных групп задач (Fan et al., 2021):

| Группа | Примеры методов |
|---|---|
| Очистка (data cleaning) | Импутация: среднее, KNN, регрессия. Выбросы: GESD, IQR, k-means, DBSCAN |
| Сокращение (data reduction) | Сэмплирование строк; извлечение и отбор признаков |
| Масштабирование (data scaling) | Min-max, z-оценка, логарифмические и сигмоидные методы |
| Трансформация (data transformation) | Дискретизация (равной ширины и частоты); one-hot, embeddings, SAX |
| Разбиение (data partitioning) | Кластеризация (k-means); деревья решений (CART) |

Платформы реализуют лишь небольшое подмножество этих методов в виде жёстко заданных правил.
